# Audyt końcowy: prywatność, technika i SEO

**Nie wykonano wdrożenia.** Eksport statyczny Next.js 15 pozostaje na Firebase Hosting Spark. Formularz i Booksy zachowały swoje funkcje i układ; nowy opt-in jest nieaktywny bez zatwierdzonej konfiguracji. Nie utworzono kont, Workerów, baz ani nie zmieniono reguł, DNS czy danych w chmurze.

## Priorytety dla właściciela

| Priorytet | Działanie / status |
|---|---|
| Krytyczny warunkowo | Jeżeli produkcyjne Storage ma reguły jak plik lokalny **i** przechowuje treści niepubliczne, publiczny odczyt jest problemem. Nie potwierdzono tego na żywo. Sprawdzić w konsoli aktywne reguły, IAM, właścicieli kluczy, dostęp do archiwum i rodzaj treści bez kopiowania wiadomości; ewentualną naprawę zatwierdzić oddzielnie. |
| Wysoki | Pomiar pozostawić wyłączony do akceptacji zgodności, kwot i przetwarzania technicznego u dostawcy. Sprawdzić produkcyjną wersję HTTP i test dostarczenia kontaktu za zgodą właściciela. Ujednolicić adres w profilach po weryfikacji na miejscu. |
| Średni | Po wydaniu sprawdzić GSC, HTTPS, nagłówki oraz PDF, przejścia Booksy na dwóch urządzeniach; rozdział bazy i limity usług kontaktu/statystyk. Sprawdzić retencję historycznych danych i aktualność opisu ich odbiorców w polityce. |
| Opcjonalny | Jedna współpraca redakcyjna na raz. Dalsze zmiany CSS i CSP dopiero po dowodach z renderowania. |

## Zastany stan i zmiany

**GA4/GTM.** Przed zmianą `GtmScript.tsx` reagował na dawny klucz zgody i umiał dynamicznie wstrzyknąć GA4/GTM; konfigurowano GA4, GTM było puste, dawny `CookieBanner` zapisywał akceptację/odmowę. Ich graf nie był osiągalny z `app/layout.tsx`, aktywne nagłówki nie zezwalały na Google Analytics, a polityka opisywała brak analityki. `docs-ga4-evidence.json` i `RAPORT-AUDYT.md` należą do archiwum: przechwycenie `dataLayer` w dawnej wersji nie jest dowodem bieżącego pomiaru, a `form_submit` po dawnym Firestore nie jest odpowiednikiem akceptacji przez Resend. Nie migrowano dawnych zgód ani nie usuwano wpisów storage użytkowników. Aktywne `PrivacyPreferences` obsługuje Booksy, który działa po własnej zgodzie i podejściu do sekcji. Mapa ładuje się na żądanie. Nie mamy dostępu do rzeczywistego panelu GA/GTM ani historii produkcyjnych żądań.

**Kod i CSS.** Przeszukano graf importów statycznych i dynamicznych od stron aplikacji, skryptów i Workera. Usunięto poniższe pliki po potwierdzeniu, że ich referencje pozostawały w usuniętym grafie lub były tylko historyczną dokumentacją. Aktywne `ContactForm`, `BooksyCalendar`, `BookingSidebar`, `BookingAndContact`, `Site`, wyszukiwarka i menu pozostają. Dawne interaktywne narzędzia psychoedukacyjne nie są częścią eksportu; statyczne materiały i PDF pozostają. CSS aplikacji, w tym `globals.css` i `editorial.css`, pozostawiono tam, gdzie użycie zależy od treści/komponentu i stanu UI; czyszczenie nie było oparte na samym dopasowaniu jednej klasy. Usunięcie martwych JSX ograniczyło generowane klasy Tailwind. `next start` nie obsługuje `output: export`; zastąpiono również nieprzypięte `serve@latest` prostym lokalnym podglądem (nie emulator Firebase). `README-FUNCTIONS.md` pozostaje odsyłaczem migracyjnym i nie uruchamia Functions.

Weryfikacja kompilacji, eksportu, SSR, URL i smoke. |

**Zależności.** `npm ci` i `npm ls --all` przeszły. Audyt przed: 1 krytyczna / 4 wysokie pozycje pakietowe (`next`, `postcss`, `sharp`, `nanoid`, `source-map-js`). Next 15.5.22 → 15.5.29 (bez Next 16, React bez migracji), PostCSS 8.5.34 z ujednoliceniem rozwiązań zależności, `nanoid` 3.3.18 i `source-map-js` 1.2.2 w dotychczasowych liniach. Opcjonalne sharp 0.35.5 mieszczące się w deklaracji Next; Node 22 w testach, minimum sharp 20.9; zalecany Node 22 także właścicielowi. Kod witryny nie udostępnia serwera optymalizatora obrazów ani Server Actions, ale aktualizacje chronią również proces budowania. Po: **0 w `npm audit`** w tej migawce rejestru; nie jest to gwarancja braku podatności. Bez `--force`. HTML+CSS gzip home: baseline 40 990 B; po czyszczeniu ok. 38,2 kB, limit testu 39 kB (baseline nie spełniał 38 kB). Statyczne assety `_next/static` ok. 1,1 MiB w obu paczkach, nie są jednym transferem na stronę. `parse5` służy testom; React/Next/Lucide oraz pipeline Tailwind są używane. Nie dodano runtime SDK.

**Hosting i dane.** `firebase.json` ma tylko `hosting`, `out/`, `cleanUrls` i końcowy slash, żadnych backendowych rewrite, predeploy wyłącznie sprawdza sitemap. Naprawiono podwójny klucz `headers` (parser JSON pomijał wcześniejszy nagłówek PDF), `Referrer-Policy: no-referrer` ujednolicono z HTML, `object-src 'none'`. `connect-src` w zwykłym eksporcie tylko self, przy konfiguracji tylko self i dokładnie zatwierdzone originy Workerów. Nie poszerzono CSP. Istniejący `frame-src` Booksy z subdomenami oraz Google Maps zachowano, bo bez realnych testów dostawcy nie można bezpiecznie zawęzić i twierdzić, że rezerwacja działa. `unsafe-inline` zachowano dla statycznego Next; osobny projekt z hashami i testami, nie szybka zmiana. `Permissions-Policy`, `X-Frame-Options` i `nosniff` pozostają. Formularz odrębnie używa Cloudflare i Resend po konfiguracji, z limitami i blokadą spamu; brak nowego kanału danych medycznych. Hosting nie zarządza starymi zasobami. Lokalne Firestore blokuje klientowi `/messages`, publicznie czyta `blogPosts`, `opinions`, `terms`; Storage pozwala czytać wszystko i pisać każdemu zalogowanemu, wbrew komentarzowi „dla admina”. To nie jest odczyt reguł produkcyjnych. Nie ma bieżącego katalogu `functions/`. Zachowany czytnik `tools/czytaj-wiadomosci/` działa poza witryną, wymaga klucza uprzywilejowanego i wypisuje treści do terminala; nie uruchamiano go. Preferować kontrolowane uprawnienia IAM, nie generować nowego klucza do audytu ani nie przekazywać zrzutów/wyjścia.

**Sekrety i logowanie.** Przegląd śledzonego drzewa i dostępnych nazw plików / wzorców klucza prywatnego oraz typowych kluczy Resend/Google nie wykazał wartości pasujących do badanych wzorców; jeden dostępny commit bazowy nie reprezentuje całej historii GitHub, chmury, logów ani plików lokalnych właściciela. Identyfikatory konfiguracji publicznej nie są poświadczeniami. Wersjonowany przykład env zawiera wyłącznie puste publiczne endpointy. `.env.*`, klucze kont, `.dev.vars*` i lokalna konfiguracja kolektora są ignorowane. Sprawdzić GitHub secret scanning i logi dostawców z zatwierdzonego konta; w razie potwierdzonego wycieku unieważnić i obrócić poświadczenie oraz zbadać użycie, nie wklejać treści do raportu. Nie twierdzimy, że nie ma danych w archiwalnych zasobach.
